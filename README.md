# 日常任务栏

Windows 桌面悬浮任务栏：每日/每周任务管理 + **屏幕识别自动打卡** + **屏幕取词式二维码识别**，界面为**暗色玻璃（Acrylic）· 克制风**。

任务可绑定"屏幕区域 + 目标画面模板 + 时间窗口"——点击 [完成] 时自动截屏做模板匹配，相似度与时间双校验通过才打勾，防止"人不在电脑前也能点完成"。

## 界面

- **原生毛玻璃**：按 Win11 22H2 `Acrylic` → Win11 21H2 `Mica` → Win10 1803+ `SetWindowCompositionAttribute` 顺序尝试，**只依赖 ctypes**、不引入第三方库；任意一步失败自动降级为自绘半透明玻璃，任何环境都有玻璃观感（主面板、任务编辑、统计面板、二维码结果窗、快捷键设置窗五处一致；托盘 / 卡片右键菜单也走同一支后端，见下）。
- **右键菜单同款观感**：菜单是**独立顶层窗口**，不在面板那棵样式树里，没人管就是系统默认浅色。托盘菜单、托盘「二维码」子菜单、卡片「更多」菜单统一走 `ui/menu.py::GlassMenu`：配色取 `theme.menu_qss()`（单一来源 `BG_MENU`），并在**每次弹出**时把主面板那套原生 Acrylic 挂到弹窗窗柄上、底板转透明。⚠️ 必须每次重挂 —— Qt 的 Popup 窗口隐藏即销毁，下次显示是新的 HWND，子菜单又是另一个弹窗；拿"已经挂过"当缓存会让菜单永远停在降级态。
- **移动窗口时自动让路**：Win10 的 `ACCENT_ENABLE_ACRYLICBLURBEHIND` 有著名的拖动迟滞（见「已知约束」），所以弹窗被移动/缩放期间会临时**撤掉** Acrylic、改由 Qt 补不透明底板顶上（**底板色在撤之前现场采样**，所以拖动前后颜色连得上），停手 260ms 后自动恢复磨砂玻璃。**不要**尝试改用 `ACCENT_ENABLE_BLURBEHIND`（软模糊）来"保住观感"——本机实测它会输出纯白且切不回来，详见「已知约束」。
- **玻璃卡片式任务行**：46px 圆角卡片（状态圆点 + 名称/周期双行 + 状态胶囊 + 完成/更多按钮），状态升级为 `待完成 / 已完成 / 验证中 / 未命中 0.xx / 已禁用` 五种语义色胶囊。
- **设计 token 单一来源**：颜色 / 字号 / 间距 / 圆角 / 阴影全部在 `src/ui/theme.py`，禁止各页面硬编码色值；字号随屏幕 DPI 自动微调。
- **暗底可读性**：显式 `Microsoft YaHei UI` + `PreferFullHinting`，文字层级按 WCAG AA 校准（主文字纯白、弱化文字 `#8B94A3`）。
- **标题栏显示版本号**：程序名右侧跟一个**更小更弱**的版本号（`FS_XS` 对标题的 `FS_LG`，间距 4px），一眼知道跑的是哪一版。文字取自 `src/ui/version.py` 的唯一来源（有静态守卫禁止别处写死版本字面量）。
- **按钮图标不依赖字体**：面板与卡片上的图标是 `src/ui/icons.py` 里用 `QPainter` **自绘的矢量图形**，不是符号字符——符号字符（如 `▦ ▩ ＋ ⋯`）在中文字体里往往没有字形，真机上会渲染成空心方块。详见「已知约束」。

## 功能

| 功能 | 说明 |
|---|---|
| 任务类型 | 每日（按日期防重复）/ 每周（每周一重置）/ 一次性 |
| 屏幕识别打卡 | 整屏定格 → 拖框 → 一步得到目标模板；完成时截屏 + numpy FFT 归一化互相关（多尺度 ±10%）；默认**全屏搜索**，按钮挪到屏幕任何位置都能识别（~1s），可切回"区域±120px"模式（更快更严） |
| 二维码识别 | 热键（默认 `Ctrl+Alt+Q`）→ 屏幕定格 → 鼠标拖框 → 识别框内二维码。**识别到链接就直接开浏览器、不弹窗**；其余内容**自动复制**并弹出结果窗（多个码可切换、是网址则多一个「打开链接」）。后端 zxing-cpp，纯 wheel 无外部 DLL；面板标题栏的二维码图标按钮与托盘「二维码」子菜单里也有入口 |
| 二维码开关 | 托盘 →「二维码」子菜单：**识别到链接直接打开浏览器**（缺省开；关掉就回到"弹窗 + 按钮"）、**识别后自动复制**（关掉后结果窗只显示内容，粘贴要自己点「复制」）、**识别到网址显示「打开链接」**（直开开启时置灰，那时弹窗根本不会出现）。三个开关缺省都是开 |
| 时间窗口 | 任务可限制验证时间段，窗口外点击不通过 |
| 手动模式 | 不需要截图验证的任务直接点击完成 |
| 打卡统计 | 近 30 天完成记录、连续打卡天数、本周完成度 |
| 贴边自动隐藏 | 拖到屏幕左/右缘吸附成 6px 细条；**轮询系统光标位置**判定靠近——压在面板上立即展开、边缘热区犹豫 100ms，离开 320ms 后 `InCubic` 平滑收回；不抢焦点 |
| 托盘 + 热键 | 关闭窗口最小化到托盘；两个全局热键**都可在托盘「快捷键设置…」里改键**（呼出面板默认 `Ctrl+Alt+T`，四态切换：隐藏/浮动/停靠收起/展开）。二维码相关的动作与开关收在托盘「二维码」子菜单里。右键菜单与主面板同款配色 + 磨砂玻璃 |
| 开机自启 | 注册表 Run 项，优先指向打包 exe |
| 位置记忆 | 面板/弹窗记住上次拖到的位置，启动（含自启）自动还原；屏幕布局变了自动夹回，托盘可重置 |
| 全屏免打扰 | 前台应用占满**面板所在那块屏**（游戏/视频/演示）时自动让位：收走窗口并停掉靠近轮询，退出全屏自动回位；按屏判定，副屏全屏不影响主屏面板；**无边框窗口铺满工作区（底下还露着任务栏）同样算**，带标题栏的普通最大化窗口不算；托盘可关 |
| 被挡住就不弹 | 停靠态靠近边缘时，先探测**面板滑出后要占的那块地方**有没有别人的窗口——有就不弹（光标压在细条上也不弹），只浮一条会自动消失的小标题「被「XX」挡住」；**停在那里 1 秒仍可强行唤出**，不用记热键。就地测量（系统命中测试逐点采样），不必知道对方是什么程序，因此伪全屏/半屏贴边/播放器全屏一律覆盖；托盘可关 |
| 失败诊断 | 匹配失败自动存截图到 `data/debug/`，任务行直接显示得分（如"未命中 0.64"） |

## 运行

**源码**（Python 3.10+）：

```bash
pip install -r requirements.txt      # 运行依赖
pip install -r requirements-dev.txt  # 开发/测试依赖（pytest / ruff）
python -m src.app
```

**打包版**：直接运行 `dist\日常任务栏\日常任务栏.exe`（onedir 结构，`data\` 自动生成在 exe 同级，整个文件夹拷走即绿色便携）。

## 打包

```bash
PYTHONPATH= python -m PyInstaller 日常任务栏.spec --noconfirm
```

或双击 `打包.bat`（GBK 编码）。产物约 128MB——OpenCV 已用 numpy 自实现替换，PySide6 无用 DLL（Quick/Qml/Pdf 等）已在 spec 中过滤。

> `PYTHONPATH=` 不能省：注入了 `sitecustomize` 的环境会阻断 PyInstaller。

## 使用要点

1. **添加任务** → 验证方式选"图像识别" → 点"框选目标画面"（本程序窗口会自动隐藏，定格全屏拖框，Esc 取消）
2. **目标模板**应是任务完成后的画面状态（如"已签到"按钮），建议框小一点、只框关键区域
3. **匹配阈值**默认 0.85：误判调高、识别不稳调低（编辑任务可改）
4. 识别失败先看 `data/debug/` 里的实际截图 vs `data/templates/` 的模板，对比差在哪
5. 编辑对话框是非模态窗口，截图过程中隐藏/恢复不会打断编辑
6. 任务名悬停可看完整名称 + 该任务的周期重置时间
7. **识别二维码**：按 `Ctrl+Alt+Q`（或在面板上点二维码图标、或走托盘 →「二维码」→「识别二维码」）→ 画面定格 → 拖一个框把二维码圈进去 → 松手即识别。**扫到链接就直接开浏览器**（内容同时进剪贴板）；扫到别的内容才弹结果窗。框小了/歪了不要紧，框大一点留白更容易识别；框选全程 Esc 取消
8. **改热键**：托盘 →「快捷键设置…」→ 点输入框后按下新组合键（Esc 取消录制）。打开这个窗口时全局热键会被临时停掉，所以录制中不会误触发动作；`必须包含 Ctrl / Alt / Win 中的至少一个`——只用字母或 Shift 会抢走正常打字
9. **调扫码行为**：托盘 →「二维码」子菜单 →「**识别到链接直接打开浏览器**」（想先看一眼链接是什么再决定要不要开，就关掉它）、「识别后自动复制」（想自己决定复制时机就关掉）、「识别到网址显示「打开链接」」（只在关掉直开时才有用，否则它会置灰）
10. **识别太慢**（模板匹配）：未命中时会把 `config.MATCH_SCALES` 整个尺度序列跑完（3440×1440 约 2.8s，命中时约 0.6s）。嫌慢可把序列收窄成 `(1.0, 0.95, 1.05)`，或改用"区域±120px"搜索模式。二维码识别不受此影响（整屏 3440×1440 约 40ms）

## 已知约束

- 仅支持 Windows（注册表自启、托盘行为、原生毛玻璃 API）
- 定格截图坐标系为虚拟桌面物理像素，高 DPI 屏已做 DPR 换算
- 匹配基于灰度模板，目标区域若有大面积动画/主题变色可能影响得分
- 模板文件存**文件名**（不放绝对路径），目录整体搬移后仍可正常识别；历史绝对路径由 `config.resolve_template` 兼容
- 截屏统一走 `core/screen.py::open_screen()`：mss 10+ 用 `MSS`、9.x 回退 `mss.mss`。**勿在别处裸调 `mss.mss()`**（该写法在 mss 10 已弃用，`tests/test_screen.py` 有静态守卫拦截）
- 全屏搜索模式下未命中需跑完 `MATCH_SCALES` 里的全部尺度（默认 5 个，3440×1440 约 2.8s），命中会提前退出（约 0.6s）
- **二维码解码的通道顺序是隐形坑**：zxing-cpp 的 numpy 入参约定是 **BGR**，而本项目所有截屏路径产出的都是 **RGB**。把 RGB 数组直接丢进去会被它当成 BGR，彩色码的亮度顺序整个反过来；今天之所以"看着没事"是它默认 `try_invert=True` 把反色结果又捞了回来，**纯属巧合**。所以 `core/qrdecode.py` 统一先转**灰度**再传（附带更快），`tests/test_qrdecode.py::test_gray_conversion_uses_rgb_channel_order` 用假引擎钉死送进去的数组是什么
- **二维码解码只跑一趟，不做多尺度**：实测（双线性缩放 / 高斯模糊 / 二次采样三组共 30 个组合）把图放大 ×2/×3 再解，"原尺寸解不出、放大后能解出"的情况**一次都没出现**，反而在 90px + 轻模糊那组把原本能解的 ×3 解坏了；40px 以下怎么放大都解不出（信息已丢失）。屏幕上的码只要人愿意去框它基本在 60px 以上。实测表见 `tests/test_qrdecode.py`
- **热键是"同时响应"而不是独占**：pynput 走低层键盘钩子，不是 `RegisterHotKey`，抢不走别人的组合键——若某个组合已被别的程序占用（如各类截图工具的 `Ctrl+Alt+A`），两个程序会一起反应。另外全局热键在**以管理员身份运行的程序**获得焦点时可能收不到（系统会话隔离）
- **Win10 上 Acrylic 拖动迟滞是 OS 级已知缺陷**：`SetWindowCompositionAttribute(ACCENT_ENABLE_ACRYLICBLURBEHIND)`（硬模糊）在 Win10 1903+ 会让被拖动/缩放的窗口严重滞后于鼠标（高轮询率鼠标更明显、松手后还会"追尾"、CPU 飙升），至今未修（EarTrumpet #349 / FluentWPF #42 / DevToys #1258 三处独立复现）。缓解办法是移动期**把硬模糊撤掉**（`glass.suspend()`）并让 Qt 用不透明底板顶上：主面板靠 `Taskbar._suspend_glass`，弹窗靠 `GlassDialogMixin` 的 move/resize 节流。新加可移动窗口时别忘了这一条。Win11 22H2+ 走系统级 Acrylic，无此问题。
- **别用 `ACCENT_ENABLE_BLURBEHIND`（软模糊）替代**：FluentWPF 作者推荐"移动期换软模糊"，思路合理，但**本机 Win10 19041 实测不可用**——在纯白衬底下它输出 `RGB(255,255,255)`（不吃 `GradientColor`，三种 tint 都一样），把窗口整块变成纯白，且随后 `apply_glass()` 也切不回 Acrylic。撤掉系统背景时 Qt 底板必须是**不透明**的。实测数据表在 `src/ui/glass.py` 顶部；`tests/test_screen.py` 有静态守卫钉死这条（防止照网上说法"优化"回去）。
- **⚠️ Win10 的 Acrylic 不吃窗口区域 → 玻璃态的"四角"本来就是方的，主面板也一样**：`ACCENT_ENABLE_ACRYLICBLURBEHIND` 是一整块**矩形**模糊，`SetWindowRgn` 切了圆角也没用（实测：给弹窗切 10px 圆角后抓真实屏幕，四角仍是模糊色 `#555352`，深色区域包围盒恰好等于整窗矩形）。探针复刻面板结构实测，**面板的深色区域同样等于整窗矩形、角点取到的也是模糊色** —— 我们看到的"圆角面板"其实是方角模糊 + 一圈 Qt 画的 1px 圆角描边。所以菜单也照抄"方角模糊 + 圆角描边"才是与面板一致，**别再用 `SetWindowRgn` 去"修"**（修不动，只会白写一段 ctypes）；真要圆角就得放弃系统模糊自绘定格快照，不值得。
- **弹窗菜单必须自己管配色与玻璃**：菜单是**独立顶层窗口**，不在任何控件的样式树里（`QMenu` 无父级时尤其如此），没人给它 `setStyleSheet` 就是系统默认浅色。用 `src/ui/menu.py::GlassMenu`，别直接 `QMenu(`（有静态守卫拦）。两个容易漏的点：① 子菜单是**另一个独立弹窗**，`addMenu("二维码")` 建出来的是普通 QMenu，得自己 new 一个 `GlassMenu` 传进去；② Qt 的 Popup 窗口**隐藏即销毁**，下次显示是**新的 HWND**，所以原生模糊必须在**每次 `showEvent`** 重挂，不能照抄主面板的"只做一次"，也别拿 hwnd 当缓存（句柄值会被系统回收复用）。
- **QSS 接管菜单后，置灰项要自己声明颜色**：禁用态不再走系统画法，而兜底那条 `QWidget { color: #FFFFFF }` 是纯白 —— 置灰项会跟可点项长得一模一样（探针抓图确认过）。托盘里「识别到网址显示「打开链接」」在直开开启时正是置灰的，看不出来就等于这个开关读不出状态。规则：`QMenu::item:disabled { color: TEXT_MUTED }`。
- **对话框底板两态**：`theme.dialog_qss("glass" | "opaque", bg)` 与 `GlassDialogMixin._glass_qss_mode` 一一对应，状态收敛在这一个变量上，别再加布尔量（第五轮"背景消失"就是状态漏组合造成的）。撤背景前必须**先补不透明底板并 `repaint()`**，反序会露窗口黑底。
- **需要被隐藏的对话框禁用 `exec()`**：hide 会终止模态循环，模态对话框被隐藏后再显示就"自动退出"了（任务编辑框踩过）。所以任务编辑框、二维码结果窗都用 `show()` + `finished`；只有"生命周期内不会被隐藏"的对话框（统计面板、快捷键设置）才用 `exec()`
- **移动期底板色必须现场采样、不能写死**：静止观感 = Acrylic 的 tint 叠在**模糊后的桌面**上，随壁纸变化；写死主题深色会让拖动的瞬间从"磨砂灰"跳成"纯黑"（实测 `RGB(82,61,53)` → `RGB(27,29,33)`，用户反馈"背景会变成纯黑"）。`glass.sample_surface_color()` 在**撤 Acrylic 之前**采窗口左右内侧窄竖带的中位色，`glass.warm_up_screen()`（`app.py` 启动调用）预热截屏实例——它只在"移动的第一帧"被用到，首次构造实测 44ms、复用后 12ms。
- **屏幕采样一律"一次分区 BitBlt"，绝不逐像素**：屏幕 DC 上的 `GetPixel` 每次调用都会强制同步一次桌面合成，实测**恰好一帧**（`12.12ms`，中位=最大）——逐像素采一块 3×36 的窄带就是 108×12ms ≈ 1.3s，GUI 线程被占住，现象就是"程序卡死"。`tests/test_screen.py` 有静态守卫拦住 `GetPixel`/`SetPixel`。
- **面板底板有两条路径**：原生模糊生效时 Qt 底板透明（背景由系统画），模糊被临时关闭（拖动）时由 Qt 补半透明底板。改样式务必走 `Taskbar._apply_surface_style()` 这一个入口，否则会出现"背景整块消失、只剩按钮和文字悬空"
- **QSS 陷阱**：`border-radius` 超过控件尺寸会被 Qt 直接忽略（胶囊要固定 `height` + 半径取半高）；`QScrollArea > QWidget > QWidget` 会命中滚动区内所有两级后代（改卡片结构时容易重新踩到，应只针对 `QWidget#listHost`）
- **鼠标穿透只能用在叶子控件上**：`WA_TransparentForMouseEvents` 会让控件**及其子树**一起退出命中链，容器（如任务卡片）一旦设上，里面的「完成 / 更多」按钮就再也点不到。拖动靠事件过滤器即可，不需要让容器穿透。**注意 `qtbot.mouseClick(btn)` 是直接投递给按钮、绕过命中测试的**，测不出这类问题——`tests/test_ui.py::test_row_buttons_are_hit_testable` 用 `QApplication.widgetAt()` 做真实命中守卫
- **测试里不要装真的全局键盘钩子**：pynput 的 Listener 是进程级低层钩子，`taskbar` fixture 被几十条用例共用，漏掉 `tests/conftest.py` 里那道 autouse 假后端替换就会一层层叠加。`test_hotkeys.py::test_tests_never_install_a_real_keyboard_hook` 兜底
- **新用到的 Qt 控件类必须自己声明底色**：`app_qss()` 顶部那条兜底规则 `QWidget { color: #FFFFFF }` 会给**所有**控件刷纯白文字，而没写过样式的控件底色来自**系统调色板**（浅色系统 = 纯白）——白字白底，整块内容看不见。`QPlainTextEdit` 就是这么栽的（`qr_result.py` 是它的首个使用点，浅色系统必现、深色系统完全看不出来）。`tests/test_theme.py` 会拦住"会显示用户数据的控件没有自己的 background 声明"，另有像素回归 `test_qr_ui.py::test_result_text_area_is_not_painted_white`。加新控件（文本区、列表、表格）时记得补规则
- **QSS 顺序即正确性**：Qt 的类型选择器同权重时**后写的赢**。任何针对具体控件类的规则都要排在兜底的 `QWidget` 规则**之后**，否则文字色会被兜底盖掉（`tests/test_theme.py::test_plain_text_edit_rule_comes_after_the_blanket_widget_rule` 钉住这条）
- **⚠️ 别拿符号字符当图标**：`▦ ▩ ＋ ⋯` 这类"看着像图标"的 Unicode 符号落在几何图形区 / 数学运算符区，**主流中文字体（Microsoft YaHei UI）没有收录** → 真机上渲染成一排空心方块（豆腐块），用户看到的就是"按钮全是小框框"。同区的 `●`（黑圆点）收录得很全，所以缺字形与否**不能靠"它看起来普通"来判断**。
  正确做法是用 `src/ui/icons.py` 的 `IconButton`（`QPainter` 自绘矢量图，与字体无关）。**不要换成"另一个更常见的符号"**——覆盖范围随系统与字体版本漂移，换了也不知道有没有换对。
  这个缺陷**在开发机上往往复现不了**（字体回退链不同），而 offscreen 测试环境连半角 `+` 都渲染成豆腐块、**根本不能用来判定字形**。所以 `tests/test_icons.py` 用两层守卫代替肉眼：`tokenize` 扫 `src/ui/` 的字符串字面量拦下冷门码位，再断言自绘图形**确实画出了预期颜色的像素**（只断言"调用了绘制函数"挡不住画歪/被裁剪/被样式盖住）
- **悬停态在 offscreen 下是"脏"的**：该平台的光标常年停在 `(10,10)`，无父级的控件 `show()` 后正好落在它下面 → 一显示就是悬停态。写像素断言前要**显式 `sendEvent(QEvent.Type.Leave)` 把基线钉成常态**，否则会读到悬停色而以为画错了（`tests/test_icons.py` 的 `bare_button` fixture）
- **⚠️ 别用 `QAction.menu()` 去遍历菜单找子菜单**（PySide6 6.11.1 实测）：它会让返回的 QMenu 包装带走所有权，**子菜单的 C++ 对象当场被删**（不用等 GC——调用完立刻 `sub.actions()` 就报 `Internal C++ object already deleted`）。`menu.actions()[0].menu()` 这种用完即弃的写法足以让整个子菜单失效。安全的取法是 `sub.menuAction()`、`sub.parent()`。当前产品代码从不调它（只持有 `taskbar.qr_menu`），但写探针/测试时极易踩——症状是"子菜单明明在，一断言就说对象已删除"
- **⚠️ 给 PySide6 的**基类**打 monkeypatch 不生效（`QMenu.exec` 实测）**：想拦住模态 `exec`，写成 `monkeypatch.setattr(QMenu, "exec", fake)` 是无效的 —— `m.exec` 仍是 `<built-in method exec of ...>`，假函数一次都不会被调用（PySide6 把这类槽从 C++ 类型解析，绕过了类字典）。**给 Python 子类（如 `GlassMenu`）打补丁才有效**，因为它落在子类自己的 `__dict__` 里。踩错的表现很难看：以为拦住了、结果真 `exec` 进了模态循环，**用例挂死**（实测 4 分钟）而不是失败。所以"退回普通 QMenu"这类回归改用扫源码的静态守卫（`tests/test_menu.py::test_no_module_constructs_a_bare_qmenu`）。
- **Python 引用存活 ≠ C++ 对象存活**：持有 `QObject` 的 Python 引用时，还要管它被销毁的那一刻。`finished → deleteLater` 之后 C++ 对象已经没了，但 Python 包装**不会跟着失效**——`x is not None` 依旧成立，再调 `.close()` 就是 `RuntimeError: libshiboken: Internal C++ object already deleted`（二维码结果窗在真机崩过一次）。
  面板对结果窗的做法是维持一条不变量：**`_qr_dialog is not None` ⟺ 这个对象还能用**，靠挂在 `destroyed` 上的 `_forget_qr_dialog()`（唯一清理入口）在销毁时把引用清成 `None`，调用点因此不必各自记得判活。
- **大小混排的文字别用 `Qt.AlignBottom` 对齐**：标题栏的"程序名 + 小号版本号"就踩过一次。看起来对齐底边＝对齐基线，其实不是——**标题标签的外框被撑满整行（28px）而文字在框里居中**，版本号标签却贴着自己的文字高度，底边对齐会让版本号的墨迹中心**低 8px、底边低 6px**，肉眼就是"掉了一格"。两个标签都在这 28px 行高里垂直居中，墨迹中心才会重合（实测差 0px）。
  推论（也是这次差点放走的一条假守卫）：**判断"文字对齐"必须量墨迹，不能量控件外框**。第一版守卫断言的是"两控件底边一致"，注入 `Qt.AlignBottom` 后**照样通过**——因为两种对齐下外框底边都是行底。`tests/test_ui.py::test_version_label_shares_the_app_name_text_line` 现在用 `QWidget.render()` 画到已知底色上取墨迹行；注意 **QLabel 自己不画背景，`grab()` 出来的透明区转成 `QImage` 是纯黑**，直接把每一行都算成"有墨迹"（量了个寂寞）
  ⚠️ 清理**必须比对身份**：旧窗的销毁信号会**晚于**新窗赋值到达（关旧建新是同步的，而 `deleteLater` 要等下一轮事件循环），无条件清会抹掉**新窗**的引用 → 下次扫码不再关旧窗 → 结果窗在屏幕上堆积。
  另外**顶层窗口不靠 Python 引用存活**（实测有无 parent 都如此——Qt 自己持有顶层 widget），留引用的理由是"下次要能 `close()` 掉它"，不是防 GC
- **测"对象已销毁"必须真的跑事件循环**：`processEvents()` 默认**不**处理 DeferredDelete，得显式 `QApplication.sendPostedEvents(None, QEvent.Type.DeferredDelete)`。少了这一步，`deleteLater` 排的队根本不执行，测出来的永远是"还活着的对象"——原先那条"扫两次会替换旧窗"的用例就是这么假绿的（它一次事件循环都没跑）
